# 总点评 General Evaluator（GE）

> 来源编号见 [research/SOURCES.md](../../research/SOURCES.md)。标注「推论」的是综合多方资料的判断，不是某位作者原话。

## 1. 一句话理解

总点评是这场会议的"质检官 + 点评团队队长"：带领点评人、计时官、语法官、哼哈官，观察整场会议从开始到结束的每个环节，最后告诉大家——哪里做得好、哪里下次可以更好。

## 2. 为什么值得做

**能练到什么**：倾听与观察、结构化反馈、即时组织语言、领导一个小团队 [G1]；以及"从系统层面看问题"的能力。

**能获得什么存在感**：
- 你的观察可以真正改变俱乐部：曾有多位总点评反复指出"没人在门口迎接访客"，那个俱乐部后来就设立了专职迎宾 [G1]。
- 你是少数被允许"评价整个会议"的人——这是一个难得的、练习对系统提出建设性意见的机会 [G1]。
- 有人觉得这个角色"太大"而回避，但正因为大，学到的也多 [G1]。

## 3. 官方职责（简版）

据 TI 官方会议角色页 [O4]：
- 评估会议中发生的一切
- 主持会议的点评环节，并负责点评团队：点评人、计时官、语法官、哼哈官
- 确保其他点评人了解自己的任务
- 向全场说明点评的目的和好处
- 会前确认计时官、语法官、哼哈官的安排；和主持人核对会议流程
- 会中记录，评估守时、热情、准备、组织、职责完成情况等

补充 [G1]：总点评也要关注点评人是否根据讲者的 Pathways 项目目标给出反馈；只有当点评人遗漏了重要内容时，才需要补充。

## 4. 会前 / 会中 / 会后

| 阶段 | 要做的事 | 依据 |
|---|---|---|
| **会前** | 联系点评团队：确认出席，讲清各自任务和本次点评的基调 | [O4][G1] |
| **会前** | 提醒点评人提前联系讲者、了解项目目标 | [O4][G1] |
| **会前** | 与主持人核对流程；准备一张按角色划分的记录表 | [O4][G3] |
| **会中** | 从会议开始（甚至入场迎接）就开始观察；按角色记录优点和具体改进点 | [G1][G3] |
| **点评环节** | 简单说明点评的意义（照顾来宾）；依次请点评人、辅助角色报告；最后给出总点评 | [O4] |
| **总点评报告** | 点评点评人；点评各角色；点评会议整体（守时、流程、氛围、访客体验）| [G1][G2] |
| **会后** | 把涉及流程/制度的建议告诉 VPE 或会长 | [G1]（推论：报告中的制度性建议需要有人接住才会落地） |

## 5. 60 / 80 / 90 分模型

> 非官方评分（v1，已根据前人经验评估），帮助 EOE 会员理解"我要做到什么程度"。

### 60 分：及格
- 会前确认点评团队都在、知道自己要做什么 [O4]
- 点评环节流程顺畅，每位点评人和辅助角色都被请上台 [O4]
- 总点评报告覆盖了主要环节，有肯定也有建议 [O4][G1]

### 80 分：靠谱的人
- 会前就带好团队、定好基调，而不是当天才见面 [G1]
- 报告具体到每个角色"下次可以怎么改"，而不是笼统的"大家都很棒" [G1]
- 认真点评点评人：他们的反馈是否具体、是否有帮助 [G2]
- 有结构地记录（例如按角色分栏的记录表）[G3]
- 照顾来宾：简单解释点评环节的意义 [O4]

### 90 分：真正优秀
- 能从个人表现看到系统问题，并提出改进建议（例如访客无人迎接、即兴总点同几个人）[G1]
- 点评有分量：敢于说出真正能帮人进步的话，而不是礼貌的客套 [G2]
- 说话方式让人愿意接受：真诚、具体、对事不对人 [G2]
- 偶尔邀请其他俱乐部的人来做总点评，给俱乐部带来外部视角——这是俱乐部层面的做法，优秀的 GE / VPE 可以推动 [G1]

## 6. 前人的三条经验

### 前人经验 01 —— 大家在等你告诉他们"哪里可以更好"
- **谁**：Lynne Cantor, DTM（伦敦 Excalibur Speakers），收录于 Jennifer L. Blanck 的文章 [G1]
- **核心观点**：她听过很多次总点评报告，自己担任了某个角色，等着听哪里可以改进，结果什么都没听到——而她明知道自己有进步空间。总点评要理解每个会议角色，才能给出准确、有用的建议，例如：主持人的过渡是否太长、讲者介绍是否帮观众做好了准备、语法官选的词是否太偏。
- **为什么有价值**：直接点出总点评最常见的问题——"只夸不评"。
- **EOE 可以怎么用**：在 EOE 的总点评记录表里，每个角色至少写一条"做得好"和一条"可以试试"。在"松弛、温情"的文化里，具体建议本身就是一种尊重（推论）。
- **来源**：[G1]

### 前人经验 02 —— 最常错过的机会：会前就带好你的团队
- **谁**：Adrian Watts, DTM（澳洲珀斯多个俱乐部会员），收录于 Jennifer L. Blanck 的文章 [G1]
- **核心观点**：总点评最常错过的，是"掌控点评环节"——在会议开始之前，就告诉每位点评人需要做什么，并为本次点评定好基调。同一篇文章也提醒：有些俱乐部干脆不设总点评，或者让主持人兼任，这会让会员和俱乐部错过宝贵的反馈。
- **为什么有价值**：把总点评从"最后上台说几句的人"变成"整个点评环节的负责人"。
- **EOE 可以怎么用**：会前一天在群里给点评团队发一条简短提醒（各自任务 + 本次关注点）。
- **来源**：[G1]

### 前人经验 03 —— 点评要有分量；不知道说什么，就问"如果是我的演讲，我会怎么改"
- **谁**：Dan Strum，纽约语言学校负责人，*Toastmaster* 杂志作者 [G2]
- **核心观点**：他认为点评不是"夸一句、批一句、再夸一句"的套路，而是真正说出能帮人进步的话；俱乐部是一个安全的地方，正适合练习深入的反馈。刚入会时他不敢点评资深讲者，后来他每次自己演讲后都给自己写一份点评，再把这个方法用到别人身上：如果这是我的演讲，我会怎么改？他也建议总点评对点评人给出更具体的反馈——这本身就是领导力。
- **为什么有价值**：解决新手最大的心理障碍："我凭什么点评比我厉害的人？"
- **EOE 可以怎么用**：作为 EOE 点评人和总点评的"心法卡片"。
- **来源**：[G2]

## 7. 踩坑指南

**第一次做最容易犯的错**
- 只夸不评，或者评得太笼统 [G1]
- 会前不联系点评团队，当天才发现有人缺席或不清楚任务 [G1][O4]
- 只盯着演讲，忽略了会议整体（开始是否准时、访客有没有被照顾）[G1]
- 重复点评人已经说过的内容（官方建议：只有点评人遗漏重要内容时才补充）[G1]

**看起来重要、其实没那么重要的**
- 每个细节都要点到——不如挑最重要、最具体的几条（推论，结合 [G1][G3]）

**投入多、收益低的**
- 写一份很长的报告却超时——总点评的报告也要守时（推论）

**只有做过才知道的**
- 很多人回避这个角色，因为觉得它"太大"——但它的学习回报也最大 [G1]
- 建议先做过几次点评人，再做总点评 [G1]
- 你的报告可能会改变俱乐部的做法 [G1]

## 8. 如果你明天第一次做总点评

只记住这 4 件事：

- [ ] **今晚给点评团队发一条消息**：确认出席，提醒各自任务。[G1][O4]
- [ ] **准备一张表**：每个角色一行，分"做得好"和"可以试试"两栏。[G3]
- [ ] **每个角色至少一条具体建议。** 不要只说"很棒"。[G1]
- [ ] **不知道说什么时，问自己**：如果这是我做的，我下次会怎么改？[G2]

## 9. 实践做法与 EOE 笔记

### 9.1 头马俱乐部的实践做法（来自前人亲身经验，EOE 默认采用）

1. **会前一天提醒点评团队**：确认出席，讲清各自任务和本次关注点。[G1]
2. **用一张按角色划分的记录表**：每个角色记 1–2 个要点（一个做得好、一个可以试试），只评表现，不复述内容。[G3]
3. **也评"不上台的部分"**：是否准时开始、访客有没有人照顾、即兴是否总点同几个人。[G1]
4. **点评点评人**：他们的反馈是否具体、是否真能帮到讲者。[G2]
5. **心法**：不知道说什么时，问自己"如果这是我做的，下次会怎么改？"[G2]
6. **偶尔请外俱乐部的人来做总点评**，带来外部视角。[G1]
