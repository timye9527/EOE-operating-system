# 产品说明 · EOE Club OS

## 定位

EOE Club OS 是 EOE 中文演讲俱乐部（十几二十个人）内部使用的入口。

**核心目标：减少俱乐部运营者的重复劳动，同时把组织经验沉淀下来。**

它**不是**：另一个 Toastmasters App、微信群、腾讯文档、演讲助手、投票软件、CRM。

## 产品原则

1. **已有成熟工具解决的问题，不重复造轮子。** 接龙在微信群；协作表格在腾讯文档；投票用成熟投票工具；计时用现有演讲助手。EOE Club OS 只放链接、放说明。
2. **只开发真正属于 EOE 自己、能降低运营成本、沉淀组织经验的部分**：成长百科、官员工作台、会后记录、嘉宾来源、运营看板。
3. **三秒知道去哪。** 一级栏目固定为：首页 / 本周例会 / 成长百科 / 官员工作台 / 运营（记录 + 看板）。不再增加一级栏目。
4. **移动端优先。** 大家几乎都在手机上打开。
5. **录入必须极轻。** 会后记录一分钟以内；如果一场会结束要填 10 分钟，设计就失败了。
6. **内容与代码分离。** 新增一篇经验 = 新增一个 Markdown 文件，不改 React 代码。
7. **数据不足时不做假图表。**
8. **遇到歧义选最简单、最容易改的方案。**

## 用户与场景

| 谁 | 打开 EOE Club OS 想做什么 |
|---|---|
| 任何会员 / 嘉宾 | 看本周例会：几点、什么主题、我演什么角色、会单/投票链接在哪 |
| 第一次接某个角色的人 | 打开成长百科：「如果你明天第一次做」清单（可勾选）、60 分怎么做、前人经验 |
| 换届的官员 | 官员交接指南 + 交接清单（可勾选） |
| 官员（VPE/VPM/VPPR…） | 打开工作台：这周该做什么、模板在哪、工具在哪 |
| Meeting Manager / VPE | 会前更新本周例会；会后 1 分钟记录 |
| 官员团队 | 看运营看板：出席趋势、嘉宾从哪里来 |

## v0.1 功能清单

| 模块 | 内容 | 实现方式 |
|---|---|---|
| 首页 | 本周例会、常用操作、成长百科、官员工作台、最近记录 | 页面 |
| 本周例会 | 日期/时间/主题/MM/TM/主要角色 + 会单/腾讯文档/接龙/投票/角色指南/会后记录/其他工具入口 | 网页编辑，存数据库；默认值来自 `content/meeting.yaml` |
| 成长百科 | EOE 成长百科：官员 / 会议角色，每个 0–9 节；可信度三级显示（EOE 已确认 / 来源编号 / 推论）；第 8 节清单可勾选；官员交接指南；资料来源总表 | `docs/eoe-growth-wiki/` 的 Markdown（唯一来源） |
| 官员工作台 | 7 位官员：职责、本周/本月/任期 checklist、模板、工具、相关百科；VPM/VPPR 显示嘉宾来源统计 | `content/workbench/*.yaml` |
| 投票 | 不自建投票。保存投票模板入口（工具名、链接、用途、备注）；本周例会可绑定投票链接（可从模板选） | `content/tools.yaml`（category: vote） |
| 会后 1 分钟记录 | 日期、主题、会员出席、嘉宾人数、嘉宾来源（点选计数 + 自定义）、备稿数量、获奖者、一句话复盘、备注 | 表单，存数据库 |
| 嘉宾来源 | 9 个默认来源 + 自定义（自定义过的会自动出现在下次选项） | `content/guest-sources.yaml` + 记录数据 |
| 运营看板 | 例会数量、平均出席、累计嘉宾、嘉宾来源、备稿数量、近期趋势（≥3 场才显示） | 从记录现算 |
| 工具箱 | Tool/Resource：名称、类别、URL、用途、备注 | `content/tools.yaml` |
